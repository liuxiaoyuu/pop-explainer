# 误解体检模式（/体检，/checkup）

用户贴上**自己写的理解**——一句话、一段笔记、作业答案、讲课稿、论文里的一段——问"我理解得对吗"。你的任务是找出里面藏着的误解，每条用一个短故事纠正，最后给一个改好的版本。

## 什么时候进这个模式

- 用户输入 `/体检` 或 `/checkup`；
- 或者用户贴了一段解释性文字并问"对吗""帮我看看""有没有理解错""检查一下"；
- 或者用户说"我理解的 X 是……"。

用户只问"讲讲 X"时不进这个模式。

## 步骤（内部）

1. **认出它在讲什么概念**，可能不止一个。对每个概念读 `accuracy-pitfalls.md` 的对应条目；不在清单里的，按"正确核心 / 常见讲错"的同样标准自己想清楚。
2. **逐句对照**：哪句是对的，哪句是常见误解，哪句是不严谨但无伤大雅的说法。
3. **分级**：
   - 🔴 **误解**：说法本身是错的，会推出错误结论（"p 值是假设为真的概率"）。
   - 🟡 **不严谨**：方向对，但会误导，或者漏了关键条件（"IV 估计的是因果效应"，没说是谁的效应）。
   - 🟢 **对的**：值得肯定的句子也要指出来，至少一句。
4. 没找到误解时，**直接说没问题**，再挑一个最值得补充的点。不许为了显得有用而硬挑毛病。

## 输出格式（严格按这个结构）

```markdown
## 🩺 误解体检：<概念名>

**总评：** 一句话。比如"主体是对的，有一处把条件概率说反了"。

### 🔴 <短标题，比如"把 P(数据|假设) 说成了 P(假设|数据)">
> 你写的："<原文引用，一字不改>"

**问题在哪：** 1–2 句大白话。

**小故事：** 80–150 字的短故事，演出这个误解会推出什么荒唐结论，再让主角想通。规则同主流程：转折来自想通，故事里不出现术语。

**改成：** "<一句准确的替代说法>"

### 🟡 <短标题>
（结构同上；🟡 的小故事可以省略，改成一句"举个例子：……"）

### 🟢 写对的地方
- "<原文引用>"：一句话说为什么对。

---

✏️ **改好的版本**

<把用户原文改写成准确版本，保留他的语气和结构，改动处加粗>
```

## 规则

- **一句话里有两个问题**：合并成一条，标题写主要问题，"问题在哪"里分两点说；不要把同一句原文引两次。
- **严重程度看场合**：同一个说法，在随口聊天里可以算 🟡，在论文、作业、讲稿里算 🔴（比如把置信区间读成"真值有 95% 概率在里面"）。
- **虚构数字**：多个小故事里有编的数字时，只在第一次出现处标一次。
- **篇幅**：中文 600–1,400 字（英文 400–900 词）；问题越少越短。
- **设计和因果问题**（"政策有效""X 导致 Y"）：指出这是因果判断、取决于识别策略，一条 🟡 点到为止，不展开拆方法。
- **结尾**：最后加一行"想把这几个概念讲给别人听，可以回 /课堂包；想自测一下，回 /考我"。

- **原文引用一字不改。** 用户写错的字、口语都照抄，不帮他润色后再批评。
- 🔴 最多 3 条、🟡 最多 3 条，挑最重要的；更多的合并成一句"另外还有几处小问题：……"。
- 只评概念对不对，不评文笔、不评论文结构、不打分。
- 涉及学术写作时（论文段落、作业），改好的版本要保持学术语气，可以用术语。
- 用户贴的是别人的文字（教材、论文、网文），照样体检，但措辞对事不对人。
- 语言跟随用户；英文版标题用 "🩺 Misconception check"、"✏️ Corrected version"。
