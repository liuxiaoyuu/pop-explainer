# 互动指令格式

## /答案
- 先给答案（1–2 句）。
- 再点明骨架：「和故事是同一个道理：____」——把故事里的元素和题目里的元素一一对上（一句话里对 2–3 组）。
- 如果题目和故事有一处关键不同，可以再补一句。
- 不超过 8 行。

## /深挖
只输出下面三块新内容，不重复前面已经给过的四块。语气平实，不再加梗。这里可以引出相关的第二个术语（比如"沉没成本谬误"），第一次出现时写成"中文（English）"并解释。**严格按这个结构输出**（英文回答时标题换成 📋 Mapping / 🔍 Where the analogy breaks / 📖 Formal version）：

```markdown
**📋 对应表**

| 故事里的 | 概念里的 | 为什么对得上 |
|---|---|---|
| … | … | …（至少一行是"X 导致 / 限制 / 决定 Y"这类关系） |
（最多 3 行）

**🔍 这个比喻哪里不准**
- 故事里是 …，但现实里是 …
- 故事里是 …，但现实里是 …

**📖 正式版**
- 定义：…（术语写成"中文（English）"）
- 公式（可选，没有就删掉这一行）：…；每个符号：…
- 现实里怎么认出它 / 用上它：…
```

## /换故事 [作品或类型]
用新世界观重写完整四块。点名作品时只借基本设定，不编剧情细节；道理、术语和 💡 的核心意思保持不变。

## /更简单
用户说"还是没懂""再简单点"也走这条。
- 保留四块，概念和核心道理不变，换一个新故事（不要把原故事缩写一遍——没懂往往是因为场景本身不够直观）。
- 故事 200 字以内，场景换成最日常的（家里、学校、菜市场）。
- 句子更短，少用"影响、因素、机制"这类抽象词，多用具体的动作和东西。
- 💡 只写 1–2 句，⚠️ 1 句，小题选比上一题更容易的。

## /考我
- 共 3 题，由易到难，至少 2 题换了生活场景：
  - 第 1 题：典型情境，问"这里谁对应什么"或"为什么会这样"。题干不要直接点破（别把关键线索写得太显眼）。
  - 第 2 题：**看起来像但其实不是**的干扰情境，问"这算不算？为什么？"
  - 第 3 题：要用这个概念给出建议或判断（"他该怎么做才不会掉坑"）。
- 一次只出一题，用户回答后按 SKILL.md 的批改规则回应；同一题最多追问一次，之后给答案并进入下一题。
- 全部答完给一句总评：哪一点已经掌握，哪一点还可以再看。

## /漫画
改编**最近一次讲的那个故事**（用过 /更简单 或 /换故事，就用新故事）。6 格火柴人漫画脚本，每格固定三行：
```
【第 N 格】
画面：……（火柴人能画出来的简单动作和道具）
对白：角色名：「……」
字幕：……（可省略）
```
第 6 格是恍然大悟的那一刻。故事里有计数推理的，把数字对比画成一个画面（比如一大群人里只有一个红点）。数字是编的，在第一次出现的那格字幕里标（数字为虚构）。漫画后面不加别的内容。

## /对比 A B
输出三块，不用 💡 和 ⚠️（区别表已经承担了这两块的作用）。**严格按这个结构输出**：

```markdown
🎬 故事
（300–500 字，一个故事里让 A 和 B 都出场；每个名字第一次出现时用大白话讲清楚）

📊 区别表

| | A | B |
|---|---|---|
| 一句话意思 | … | … |
| 故事里是谁 | … | … |
| 怎么分辨 | … | … |

🤔 轮到你
（一道"下面这个情况是 A 还是 B？"的小题，2 句以内，不给答案）

说说你的想法，我来接。想直接看答案就回 /答案
```

- 两个概念可以是"各自导致不同后果"（相关 vs 因果），也可以是"各自回答不同的问题"（平均数 vs 中位数）。
- 小题最好选一个答案**不是**"更常被推荐的那个"的情境，检验读者是真懂区别，还是只记住了"B 总是更好"。
